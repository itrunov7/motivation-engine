# /dossiers — Admission gate records

## What lives here

- `dossier.schema.json` — schema for dossier records.
- One JSON dossier per lifecycle decision, shaped as:
  `{ id, mechanism_id, scores{…}, total, core_condition, dissent, evidence_sources[], verdict, decided_by, date, notes }`.

A dossier scores a mechanism on five axes (0–3 each): `evidence`,
`product_applicability`, `measurability`, `orthogonality`, `safety`. Each axis
is `{ score, rationale }`, where the rationale is markdown — the scientific
reasoning is part of the record, not decoration (Option A: JSON is the single
source of truth, `/dossiers` renders the markdown). The record also carries a
markdown `dissent` statement (every dossier must address counter-evidence,
D-019), a `core_condition` (the measured condition for promotion to core), and
`evidence_sources[]` as `{ ref, doi? }`.

Thresholds: *incubating* requires total ≥ 11 AND `scores.evidence.score` ≥ 2
AND `scores.safety.score` ≥ 2; *core* additionally requires at least one
measured effect. The validator checks `total` equals the sum of
`scores[*].score`.

Dossiers are the only way a mechanism moves through the lifecycle
(candidate → incubating → core). The showcase displays statuses; it never
changes them.

## Filled by

Owner decisions, entered in git — never generated by code. The app renders
dossiers, it never scores them.
